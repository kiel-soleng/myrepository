## Plan (approved implicitly — first test build, not a real prospect)
- **Data inventory.** Five synthetic departments (4 expense, 1 revenue),
  12 trailing months, budget + actual only — no GL line-item detail yet.
- **Inference rationale.**
  - KPI row: Total Budget / Total Actual / Variance $ / Variance % — the
    four numbers a CFO reviews first.
  - Variance-by-department bar chart *substitutes for a waterfall*, which
    `sigma-workbook-conventions` confirms is **not supported** by
    workbooks-as-code. Flagging here per that doc's guidance to surface the
    gap rather than attempt the unsupported kind.
  - Department detail table sorted by the SQL's own `ORDER BY` (not a spec
    `order` field — that only controls table column order, not row sort).
  - Trend chart needs the full 12 months regardless of the period filter,
    so it sources from a **second, unfiltered copy** of the same SQL
    (`tbl-budget-actuals-trend`) rather than the filtered `tbl-budget-actuals`
    — a control's `filters[]` scopes every element chained off the element
    it targets, per "Control wiring" in `workbook-spec-api.md`.
- **Filter set.** One `list` control (`ctrl-period`, single-select) on
  Period Month, filtering the KPI row + variance chart + department table
  only.
- **Layout sketch.** Header (title + period control) / KPI row (4-up) /
  variance-by-department bar / department detail table / 12-month trend /
  two raw source tables placed at the bottom (validator requires every
  element to appear in the layout XML, per the exemplar's own pattern of
  placing its base table).
- **Open decisions (yes/no for whoever POSTs this):**
  1. OK to ship the bar-chart substitute for the requested "variance
     bridge/waterfall" look, or hold for a real waterfall built in the UI
     post-creation?
  2. Fiscal period in the page title is a placeholder ("FY26") — confirm
     or replace before this goes in front of anyone.
